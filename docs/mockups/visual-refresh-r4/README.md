# Visual refresh — round 4: flow walkthroughs + a UX-driven redesign (Aug 2026)

Round 3 settled the shell (Grimoire flanks, Gallery center). Round 4 audits the
three core flows in the current app — walked in the real renderer via the
preview harness — and redesigns the center around them. The Grimoire soul is
kept: notched bookmark rail, sigil rings, wax-seal DUCK, ornament rules.

## Walkthrough A — adding local media / a YouTube video, tagging (current app)

1. `+ Add audio` (top bar) or `Import` (library header) → **modal** opens over everything.
2. Pick Source (Link / Local files). Local files: the picker only opens when you press
   the submit button ("Choose files…") — no drag-and-drop anywhere, no preview of what you picked.
3. Pick Type (Music / Ambience / Soundboard) — must be decided before you see what a
   playlist URL actually contains.
4. Pick tagging strategy up front: "All at once" (one tag set for everything) or
   "One by one" (import first, then tag each item inside the same modal).
5. Batch: modal closes on import with no landing report; duplicates are silently skipped.
   Per-item: a long scrolling modal of TagPickers, with **no way to listen** to the item
   you're tagging, and closing loses the session.
6. Fixing tags later = hover a row → 16px edit icon → another modal. No multi-select.

**Frictions:** modal tunnel blocks the whole app; tagging is blind (no audition);
decisions front-loaded; no drop-target; no dedupe/normalization feedback; tiny hover
targets; no batch re-tag.

## Walkthrough B — creating a scene from existing assets (current app)

1. Scenes are **snapshots of the live mix** — there is no authoring surface. You must
   build the real, currently-sounding mix: queue tracks, switch the library tab to
   Ambience, double-click layers in, set every volume.
2. Then find the 16px film icon in the mix pane header → "Save as Scene" modal:
   a name field, nothing else.

**Frictions:** to prep the *next* scene you must destroy the *current* one — the
biggest architectural gap (mid-session prep is impossible); the save affordance is
nearly invisible; a scene can't be reviewed or edited after saving except by
recalling it live (destructive, guarded by a native `confirm()`).

## Walkthrough C — opening a scene, finding media in it, playing (current app)

1. Scenes rail → click → native confirm ("Unsaved changes will be lost") → crossfades in.
   One-click recall itself is genuinely good.
2. A scene's contents are **invisible until you load it** — the rail shows only
   "2 tracks · 1 layer". After recall the contents scatter into the queue/ambience panes
   with no "this is scene X" framing.
3. Search filters the *library* only — you cannot search within a scene, and playing a
   specific track means hunting the queue's hover-only controls.

**Frictions:** contents hidden pre-recall; no scene-scoped search; recall is all-or-
nothing (no "just the ambience"); no way to audition a scene without broadcasting it.

## The redesign — four moves, five screens

1. **Chapters are pages you write, not snapshots you take.** A scene is an editable
   document (melody / undertones / sigils + volumes). "Live" is just whichever page is
   on air; you author, edit, and rehearse other pages while it plays. Snapshot-from-live
   survives as "Bind what's sounding now".
2. **Import is a workbench, not a modal.** Drop files or paste a link; items land in an
   "Arriving now" table with per-row audition, inline type/tags, dedupe + loudness
   status. Untagged items wait on an **Unsorted shelf** — importing never blocks anything.
3. **Tagging is keyboard-first, with your ears.** A triage view auditions each item in
   the monitor only, chips + a type-ahead tag field (`tav` → Location · Tavern),
   Enter-saves-and-advances, tags copy forward within a batch.
4. **Rehearse vs Take the stage.** Every page can play into the monitor without
   touching the table, and goes live through one big amber action with partial-recall
   toggles. ⌘K (the Seeker) searches scoped: this chapter / the library / actions.

| File | Screen | Covers |
|------|--------|--------|
| `x1-scriptorium` | The Scriptorium — import workbench with arriving-now table and Unsorted shelf | Walkthrough A |
| `x2-triage` | Tag as you listen — audition-first keyboard triage with type-ahead tags | Walkthrough A |
| `x3-binding` | Writing a chapter — library palette + editable page, draft bookmark in the rail, on-air chapter untouched | Walkthrough B |
| `x4-chapter` | An open chapter — contents visible, scoped search, start-anywhere play, Rehearse / Take the stage | Walkthrough C |
| `x5-seeker` | The Seeker — ⌘K over the chapter, results grouped by scope with add-to-chapter actions | Walkthrough C |

## Revision (same round)

- Loop/timing became real controls, not prose: per-layer **Loop / Random**
  segmented toggle, `every [− n +] to [− n +] min` steppers for random layers,
  `when the list ends: loop last track ▾` and a crossfade stepper on the music list.
- Theme language reduced to visuals only. Chapters → **Scenes**, The Melody →
  **Music**, The Undertones → **Ambience**, Sigils → **Soundboard** (the ring
  visual stays), Take the stage → **Play scene**, Rehearse → **Preview — only
  you hear it**, Bind → **Copy current mix into this scene**, Save chapter →
  **Save scene**, Scriptorium → **Import audio**, Unsorted shelf → **Untagged**.
